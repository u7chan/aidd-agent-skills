# 概要

実装に入る前に、調査・要求整理・要件定義・設計・検証計画を進めるための入口スキル。
目的が曖昧な場合は、最初に「今回ほしい成果物」を一つだけ確認する。

## 初動

ユーザーの依頼から目的が明確に判断できる場合は、その目的に合わせて進める。
判断できない場合は、次の選択肢を提示して一つ選んでもらう。

```md
質問: 今回の plan で主に作りたい成果物はどれですか？

選択肢:
  1. 調査して判断材料を作る
  2. 要求・要件・ドメインを整理する
  3. 設計案や ADR を詰める
  4. PoC・スパイク・検証計画を作る
  5. ただ壁打ちしたい
```

## 進め方

- 質問は一度に一つずつ行う。
- コードベースや既存ドキュメントの調査で答えが得られる場合は、質問する前に調査する。
- 不明点が複数ある場合は、依存関係の上流にあるものから確認する。
- 設計上のリスク、未決定事項、暗黙の前提、既存資料との矛盾を見つけたら優先して掘り下げる。
- まだ実装しない。
