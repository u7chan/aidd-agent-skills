# PR作成

品質確認後、PR 作成に入る直前に参照する。

## 手順

作業ブランチを push し、PR を作成する。

- PR タイトルは変更内容を簡潔に表すものにする。
- Issue を閉じる場合は `Close #<no>`、関連付けのみなら `Refs #<no>` を使用する。
- `Changes` は少量なら箇条書き、変更が多い場合は領域や目的ごとにグループ化して構造化する。
- PR 本文は必ず本テンプレートで作成する。他のテンプレートは使用しない。

```markdown
## Issues

<!-- Close #<no> or Refs #<no> -->

## Why

<!-- 変更が必要な背景を書く -->

## Summary

<!-- この PR の概要を書く -->

## Changes

<!--
少量なら箇条書きで書く。

- 変更点 1
- 変更点 2

変更が多い場合は、領域や目的ごとにグループ化する。

### <group>

- 変更点 1
- 変更点 2
-->

## Verification

<!--
- `command` - passed
-->
```
